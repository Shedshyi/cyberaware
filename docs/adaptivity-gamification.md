# CyberAware: адаптивность, геймификация и дизайн эксперимента

Описание того, что реализовано в платформе CyberAware на 18 ноября 2026 года (ветка `feature/backend`). Текст можно использовать в главах диссертации о разработке платформы и методике эксперимента. Здесь описано только то, что есть в коде и проверено тестами или вручную в браузере.

## 1. Дизайн эксперимента в платформе

### 1.1. Две группы

Каждый участник после информированного согласия попадает в одну из двух групп:

| | Экспериментальная группа | Контрольная группа («традиционный режим») |
|---|---|---|
| Уроки (теория, факты, разбор случая, видео) | есть | есть |
| Практические тесты с разбором ошибок | есть | есть |
| Подсказки в практических тестах | есть | нет |
| Интерактивные тренажёры (6 шт.) и Hacker Game | есть | нет |
| Адаптивность: «Следующий шаг», подбор сложности, панель «Как тебя видит платформа» | есть | нет |
| Геймификация: опыт, звания, медали, награды, дневная цель, серия, сюжет | есть | нет |
| Анкета, входной и итоговый тест | одинаковые | одинаковые |
| Сбор данных | одинаковый | одинаковый |

Таким образом, сравнение групп проверяет гипотезу «интерактивная, геймифицированная и адаптивная платформа повышает цифровую грамотность сильнее, чем обычное обучение по тем же материалам».

Технически режим определяется в `src/research/experience.jsx`. Маршруты тренажёров и сертификата закрыты для традиционного режима: при попытке открыть их участник перенаправляется к урокам. Гости и работа без подключения к Supabase получают полный режим, но в исследование не попадают.

### 1.2. Распределение по группам

Группа назначается **в момент согласия**, а не при регистрации. За это отвечает функция базы данных `assign_cohort()` (миграция `supabase/migrations/003_adaptive.sql`):

1. Берётся блокировка (`pg_advisory_xact_lock`), чтобы два участника, согласившиеся одновременно, не попали в одну и ту же «меньшую» группу.
2. Считается, сколько участников с согласием уже в каждой группе.
3. Новый участник попадает в группу, где людей меньше. При равенстве группа выбирается случайно (50/50).
4. Повторный вызов группу не меняет. Сменить её сам участник не может: права на изменение поля `cohort` у него нет.

В результате при любом числе участников группы отличаются не больше чем на одного человека. Время назначения сохраняется в `profiles.cohort_assigned_at`, а событие — в журнал (`cohort_assigned`).

### 1.3. Порядок для участника

Регистрация → согласие и анкета → входной тест (20 вопросов) → обучение в своём режиме → итоговый тест (те же 20 вопросов; открывается после 5 разных практических тестов) → результат и прирост. Пропустить шаг нельзя: до согласия и входного теста сайт возвращает участника к нужному экрану (`src/research/ResearchGate.jsx`).

### 1.4. Чистота измерения

Входной и итоговый тест одинаковы для обеих групп и не зависят от режима:

- без подсказок, рекомендаций, опыта и уведомлений: эти компоненты на страницах тестов не подключены;
- правильные ответы не показываются, участник видит только итоговый балл;
- вопросы и порядок вариантов фиксированы (`src/research/assessmentData.js`);
- дополнительно записывается только время ответа на каждый вопрос (`answers.response_ms`).

Результат входного теста по темам после его сдачи используется как стартовая оценка знаний для адаптивности (раздел 3.2). Сам тест от этого не меняется.

## 3. Адаптивность

### 3.1. Модель поведенческой оценки

Реализация модели из статьи N. Jambul, R. Akhitova, «Fuzzy Logic-Based Behavioral Assessment Model for Adaptive Cybersecurity Education», IEEE DG 2026, ID137. Код: `src/adaptive/fuzzy.js`. В статье приведены не все детали, поэтому часть модели достроена. Ниже это явно разделено.

**Слой 1. Наблюдение.** На каждый ответ записываются x₁ — правильность, x₂ — время ответа в секундах, x₃ — использование подсказки, x₄ — сложность (1 — Easy, 2 — Medium, 3 — Hard).

**Слой 2. Нормализация и сигналы.** Оценивается сессия из последних N = 10 ответов. Время нормализуется в [0, 120] с с отсечением, окно для временных сигналов W = 5.

| Сигнал | Формула | Источник |
|---|---|---|
| WA, взвешенная точность | Σ(x₁·x₄) / Σx₄ | статья |
| GS, угадывание | быстрые неверные ответы на сложных / все сложные; «быстрый» — меньше 10 с | формула из статьи, порог достроен |
| HP, давление подсказок | Σx₃ / (Σx₁ + ε); для нечёткого слоя отсекается до 1 | статья |
| FI, усталость | max(0, r(позиция, время)) · max(0, −r(позиция, верность)) в окне W, где r — корреляция Пирсона | идея из статьи («одновременный рост времени и падение точности»), формула достроена |
| SS, плато | (1 − min(1, σ²(WA по окнам W) / 0,25)) · (1 − WA) | идея из статьи («дисперсия WA по окну»), формула достроена |

Множитель (1 − WA) в SS нужен, чтобы стабильно высокая точность не считалась застоем. В статье профиль A имеет SS = 0,08 при стабильно верных ответах, и формула это воспроизводит.

**Слой 3. Нечёткий вывод Мамдани.** Функции принадлежности входов — треугольные, по таблице I статьи. Импликация min, агрегация max, дефаззификация центроидом на шкале [0, 100]. База — 20 правил:

| Правило | WA | GS | HP | FI | SS | Вывод | Источник |
|---|---|---|---|---|---|---|---|
| R1 | H | L | L | L | L | Advanced | статья (SS добавлен) |
| R2 | H | H | L | L | | Intermediate | статья |
| R3 | H | L | H | | | Intermediate | достроено |
| R4 | H | L | L | H | | Intermediate | статья |
| R5 | M | L | L | L | | Intermediate | статья |
| R6 | M | H | L | L | | Beginner | статья |
| R7 | M | | H | | | Beginner | достроено |
| R8 | M | L | | H | | Intermediate | достроено |
| R9 | M | L | | | H | Intermediate | достроено |
| R10 | L | | | | | Beginner | статья |
| R11 | H | L | L | L | H | Intermediate | статья |
| R12 | H | L | L | L | M | Advanced | достроено |
| R13 | H | M | | | | Intermediate | достроено |
| R14 | H | L | M | L | | Advanced | достроено |
| R15 | H | L | L | M | | Advanced | достроено |
| R16 | H | H | H | | | Intermediate | достроено |
| R17 | M | M | | | | Intermediate | достроено |
| R18 | M | | M | | | Intermediate | достроено |
| R19 | M | H | | H | | Beginner | достроено |
| R20 | H | H | | H | | Intermediate | достроено |

Пустая клетка означает «любое значение». В правило R1 добавлено условие SS = Low: без него R1 и R11 совпадали бы по условиям.

Выходные функции принадлежности (достроено): Beginner [5, 30, 50], Intermediate [35, 62, 85], Advanced [60, 88, 100].

**Слой 4. Поправка на уверенность** (статья): C = 1 − 0,4·GS − 0,3·FI, S_adj = S·C.

**Слой 5. Выход.**
- Уровень по S_adj (пороги достроены): Advanced при S_adj ≥ 65, Intermediate при S_adj ≥ 35, иначе Beginner.
- Правило безопасности (статья): три и более неверных ответа подряд в сессии дают уровень Beginner независимо от остального.
- Поведенческий профиль (пять профилей из статьи; правило выбора достроено): первый сигнал, перешедший в зону High, в порядке угадывание → усталость → подсказки → плато. Если такого нет — Consistent. Порядок соответствует обоснованию α > β в статье: угадывание искажает оценку сильнее усталости.

**Проверка модели.** Автотесты (`npm test`, файл `src/adaptive/fuzzy.test.js`) подают на вход сигналы из таблицы III статьи и сравнивают результат с таблицей IV:

| Профиль | S (статья → модель) | C | S_adj (статья → модель) | Уровень | Профиль |
|---|---|---|---|---|---|
| A | 82,4 → 82,3 | 1,00 → 1,00 | 82,4 → 82,3 | Advanced ✓ | Consistent ✓ |
| B | 61,7 → 60,6 | 0,70 → 0,70 | 43,2 → 42,4 | Intermediate ✓ | Guessing ✓ |
| C | 28,3 → 28,1 | 0,77 → 0,77 | 21,8 → 21,5 | Beginner ✓ | Fatigued ✓ |

Уровни, профили и коэффициент уверенности совпадают точно, оценки S и S_adj — в пределах 1,1 балла. Дополнительно модель правильно классифицирует синтетические последовательности из 10 ответов (4 Easy, 3 Medium, 3 Hard), построенные по словесному описанию профилей A–C в статье. Отдельно проверено правило безопасности K = 3.

### 3.2. Модель ученика

Код: `src/adaptive/learner.js`. По журналу взаимодействий строится:

- **Оценка по каждой из 10 тем курса.** Нечёткая модель на последних 10 ответах по теме, если их не меньше 3. До этого тема считается неоценённой.
- **Общая оценка поведения.** Модель на последних 10 ответах вообще.
- **Стартовое знание по входному тесту.** По 2 вопроса на тему: обе верно — «знает», одна — «частично», ни одной — «слабо».

Сложность вопросов практических тестов размечена разработчиком (`src/adaptive/items.js`): 17 Easy, 21 Medium, 12 Hard. Критерий: Easy — узнать понятие или очевидное правило; Medium — применить правило в ситуации; Hard — понимать механизм атаки или защиты. Разметку стоит подтвердить экспертами.

### 3.3. Политика «Следующего шага»

Платформа всегда показывает **один** следующий шаг и причину простыми словами (карточка на главной, в уроках, в профиле и на экране результата теста). Порядок проверки:

1. **Усталость** (профиль Fatigued и последний ответ меньше 20 минут назад) → короткий перерыв.
2. **Угадывание** (Guessing) → практический тест темы «в спокойном темпе».
3. **Опора на подсказки** (Hint-Dependent, при WA ≥ 0,4) → тест без подсказок. При меньшей точности полезнее вернуться к материалу, поэтому этот шаг пропускается.
4. **Слабая тема.** Модель оценивает тему как Beginner или тест не сдан (< 75%) → повторить урок или тест. Выбирается тема с наименьшей оценкой.
5. **Урок прочитан, тест не пройден** → тест этой темы.
6. **Следующий урок.** Сначала темы, слабые по входному тесту, затем неизвестные, частично известные и известные.
7. **Всё пройдено** → итоговый тест (если открыт) или сложные раунды Hacker Game.

Каждый показ и каждый переход записываются (`rec_shown`, `rec_clicked`), так что можно посчитать, как часто участники следовали рекомендациям. Политика покрыта автотестами (`src/adaptive/learner.test.js`).

### 3.4. Подстройка заданий

- **Подсказки в практических тестах.** Кнопка «Подсказка» убирает один неверный вариант. Факт использования записывается как x₃.
- **Hacker Game** подбирает параметры игры по модели (тема «Фишинг» или общая оценка):

| Уровень | Лёгкие / средние / сложные раунды |
|---|---|
| Beginner | 50% / 35% / 15% |
| Intermediate | 30% / 40% / 30% |
| Advanced | 15% / 35% / 50% |

Профиль Guessing увеличивает время на раунд с 12 до 20 секунд («не спеши»). Профиль Fatigued сокращает игру с 8 до 5 раундов. Выбранные параметры показываются игроку («Подобрано под твой уровень») и записываются в журнал (`adaptation`).

- **Прозрачность.** В профиле есть панель «Как тебя видит платформа»: общий уровень, поведенческий профиль с пояснением, уверенность оценки и уровень по каждой теме.
- **Оценка уровня на главной** (10 вопросов с подсказками и таймером) использует ту же модель и показывает пять сигналов, уровень и профиль.

## 4. Геймификация

### 4.1. Принципы

Геймификация опирается на теорию самодетерминации (Deci & Ryan): поддержка компетентности, автономии и причастности. Отсюда правила реализации:

| Потребность | Как поддержано |
|---|---|
| Компетентность | медали мастерства по темам зависят от знаний (результат теста, оценка модели), а не от числа попыток; звания показывают рост |
| Автономия | порядок тем свободный; рекомендация — совет с причиной, а не требование; дневная цель небольшая |
| Причастность | сюжет «центра киберзащиты»; общий прогресс команды экспериментальной группы (только сумма, без имён) |

Ограничения, введённые сознательно: опыт никогда не отнимается, плохой результат не наказывается, рейтинга участников нет. Пропуск дня в серии прощается раз в неделю. Тон всех сообщений поддерживающий.

### 4.2. Механики

Код: `src/game/engine.js` (правила, покрыты тестами `src/game/engine.test.js`), `src/game/content.js` (тексты RU/EN).

**Опыт:**

| Действие | Опыт |
|---|---|
| Впервые открыть урок | 20 |
| Пройти практический тест | 10 + 5 за каждый верный ответ |
| Впервые сдать тему (≥ 75%) | +30 |
| Улучшить свой лучший результат по теме | +10 |
| Верный раунд в Hacker Game | 2 |
| Пройти оценку уровня на главной | 15 |
| Выполнить дневную цель | 20 |

**Звания** (сюжет: стажёр центра киберзащиты): Стажёр (0) → Младший аналитик (120) → Аналитик (300) → Старший аналитик (550) → Защитник (900) → Эксперт центра (1400 опыта).

**Медали мастерства по каждой из 10 тем (миссий):**
- «Начата» — урок открыт;
- бронза — тест пройден хотя бы раз;
- серебро — тест сдан на 75% и выше;
- золото — тест сдан и модель оценивает тему как Advanced, или тест сдан на 100%.

**Дневная цель:** 40 опыта за день, примерно один урок и один тест. **Серия** — сколько дней подряд выполнена цель; один пропуск в неделю закрывается «заморозкой».

**Награды (9):**

| Награда | Условие |
|---|---|
| Первая миссия | сдать первую тему |
| Половина пути | серебро в 5 темах |
| Полный курс | серебро во всех 10 темах |
| Мастер | золото в 3 темах |
| Сам справлюсь | сдать 3 теста без подсказок |
| Работа над ошибками | пересдать на зачёт тему, которая не получилась |
| Детектив | 75% верных раундов в Hacker Game |
| Три дня подряд | серия 3 дня |
| Неделя практики | серия 7 дней |

**Сюжет.** Над каждым уроком — брифинг миссии в одну строку. Например, для урока «Фишинг»: «Бухгалтерия получила письмо „от директора“ с просьбой срочно перевести деньги. Найди подвох».

**Интерфейс:**
- короткие уведомления об опыте, дневной цели, новой награде и звании;
- карточка «Карьера» в профиле: звание, шкала опыта, кольцо дневной цели, серия, карта миссий, награды;
- медали на карточках уроков;
- звание и опыт в меню профиля.

**Общий прогресс команды** — функция базы `team_progress()` (миграция `004_gamification.sql`). Она возвращает только два числа: сколько участников в экспериментальной группе и сколько тем они сдали вместе.

Состояние геймификации хранится в браузере и восстанавливается с сервера при входе: опыт — по событиям `xp_awarded`, награды — по `badge_earned`, лучшие результаты — по попыткам тестов. Так оно не теряется при смене устройства.

## 5. Ограничения реализации

- **Часть модели достроена.** 13 из 20 правил, выходные функции принадлежности, пороги уровней, порог «быстрого» ответа и формулы FI и SS отсутствуют в статье и достроены так, чтобы воспроизвести её таблицы III–IV. Проверка модели проведена только на значениях из статьи и синтетических последовательностях, на реальных данных модель пока не валидирована.
- **Сложность заданий размечена разработчиком** и требует экспертного подтверждения.
- **Подбор сложности есть только в Hacker Game.** Остальные тренажёры имеют фиксированное содержание: их ответы записываются и учитываются моделью, но порядок и сложность заданий в них не меняются. Тренажёр «Проверка паролей» не имеет правильных ответов, поэтому записывается только факт его открытия.
- **Политика «Следующего шага» — набор правил,** её эффективность отдельно не проверялась.
- **Подсказки** есть в практических тестах и в оценке уровня на главной. В тренажёрах подсказок нет.
- **Контрольная группа тоже записывает** практические ответы во взаимодействия, но адаптивность и геймификация у неё не работают. Это сделано, чтобы данные о поведении были сопоставимы.
- Для работы нужны миграции `003_adaptive.sql` и `004_gamification.sql`. Без 003 сайт работает, но группа назначается старым способом (монетка при регистрации) и новые поля не записываются.

## 6. Перед запуском эксперимента

1. Применить в Supabase миграции `003_adaptive.sql` и `004_gamification.sql`.
2. Выключить подтверждение почты (Authentication → Sign In / Providers → Email → Confirm email).
3. Удалить тестовые аккаунты (Authentication → Users).
4. Провести пилот на 3–5 людях в обоих режимах (исследователь может переключать вид на странице результатов).
5. Опубликовать сайт (`npm run build`, затем `npx gh-pages -d build --nojekyll`).
